# 06. My Contribution & AI Workflow

## 본인 역할
아래 내용은 제공된 개발기여 히스토리에 기록된 디렉터/기획 주도 의사결정 및 플레이 기반 피드백을 요약한 것입니다. 실제 본인의 수행 범위와 프로젝트 참여 형태를 확인한 뒤 표현을 확정합니다.

### 기획 의사결정 사례
1. 클래스 수를 2개에서 4개로 확대하는 방향 결정
2. 화염술사의 핵심 자원을 Burn 중심에서 Ember 축적·폭발 구조로 전환
3. 시작 덱을 8장으로 유지해 덱 압축 경험 보존
4. 세이브/로드를 모바일 플레이에 필요한 기능으로 판단해 우선순위에 반영
5. 카드·적·포션 콘텐츠 볼륨 확대 방향 결정
6. 카드 도감, 물약 도감, 유물 도감 및 필터·강화 비교 UX 제안

### 플레이 테스트 기반 개선
- 맵 스크롤이 현재 진행 위치를 반영하지 않는 문제 제기
- 세이브/로드 이후 다음 노드가 선택되지 않는 문제 제기
- 저장 후 이전 진행으로 회귀할 수 있는 허점 지적
- 보상 선택 시 현재 덱을 확인할 수 있는 UX 요청
- 카드·포션·상태효과의 정보 가독성 문제를 스크린샷과 함께 전달

## AI 협업 방식
- AI를 기획 초안, 콘텐츠 데이터 초안, 코드 수정 지원, QA 관점 검토, 이미지 생성 프롬프트 작성 등에 활용
- AI 산출물을 그대로 채택하기보다 플레이 결과와 기획 의도에 맞춰 검토·수정
- QA 및 밸런스 검토를 통해 오류 가능성과 시스템 모순을 식별
- 이미지 생성 후 크롭·투명화·리사이즈·Unity 연결 과정의 파이프라인을 활용

## 에셋 제작 관련 기록
개발 기여 히스토리에는 16개 이미지 생성에서 시작해 Python PIL로 95개 스프라이트를 자동 처리하고 SpriteManager로 ID 기반 매핑한 기록이 있습니다. 해당 수량은 당시 문서 기록이며 현재 프로젝트 파일과 대조가 필요합니다.

## 정확한 역할 표기
- 기획 방향·우선순위·플레이 테스트 피드백: 본인 주도 여부 확인
- 초안 작성·코드 제안·에셋 처리: AI 지원 여부 및 본인 검수 범위 명시
- 실제 코드 작성자나 구현 담당을 본인이 아닌데 본인 개발로 표현하지 않기
